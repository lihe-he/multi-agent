# 任务终端协议

终端协议为 1，SQLite schema 为 10；API 和 Worker 帧协议仍为 1。终端附着于任务已经准备并核验的独立 CLONE 或 WORKTREE 目录。本文说明实现边界，实际平台与发行物结果以[实施记录](./implementation-status.md)中的准确产物回执为准。

## 建立与归属

任务自动执行和原根收尾完成后，在任务详情“终端”页选择“新建终端”。核心在同一事务中保存原启动请求、终端、`USER_TERMINAL` 根尝试、持久待派发动作和工作区写入意图。请求只包含不可变的 `requestId` 和初始尺寸；客户端不能另选目录、可执行文件、命令或环境。

Windows 使用固定 `SYSTEM_CMD` 方案，启动系统 `cmd.exe /D /Q /K` 并设置 UTF-8 代码页；POSIX 使用固定 `SYSTEM_SH` 方案，启动规范系统 `/bin/sh -i`。实际后端类、PID、出生时间、原生加载目录与摘要另行记录，不能由请求选择 ConPTY 就推断实际一定使用 ConPTY。

原 Worker 保持一个完整的 `TERMINAL` 调用。原操作租约、根执行、节点、仓库绑定版本、授权版本、目录文件身份和实际写入锁贯穿终端生命周期。终端活动不消耗模型调用预算，也不需要重新取得模型密钥。自动继续、验证、撤销和验收按同一工作区门禁等待原终端收尾。

终端以当前系统账户运行，独立目录和平台授权检查不构成操作系统沙箱。界面在启动前说明输出持久保存、命令可能回显、人工修改使当前验证和审查失效。任务当前目录、项目会话级终端、远程终端与远程恢复继续实施。

## 查看、控制与重连

新页面默认“仅查看”。离开任务、切换页签或重新加载只卸载查看者，原 shell 保留；页面不会重发启动请求或人工输入。排队和启动分别显示“等待原终端领取”“正在启动原终端”，继续读取同一个原终端。

多个查看者可以读取输出，同一时刻只有一个显式控制者。取得或接管控制须提供当前代次，核心生成新的代次与控制凭据；接管等待此前实际派发的动作收尾。凭据只在已认证的请求体及当前客户端内存中传递，URL、shell 环境和交付包不携带它。旧代次不能输入或调整尺寸。

查看者不改变原尺寸。取得控制后，xterm 和 FitAddon 根据实际面板及字符单元测量尺寸，服务器 ACK 绑定相应代次。窄屏、重新打开和重新加载保留原 PID 与出生；新页面通过重读输出建立显示，不重新执行命令。

输入、粘贴、尺寸调整与停止串行处理。每个动作保存不可变的请求编号、序号、类型、长度与摘要，实际输入字节不写入动作历史。相同编号和相同事实返回原回执；内容冲突、过期代次和无序请求被拒绝。原意图、派发、一次原生授权与 ACK 分别记录。

输入响应丢失时，客户端只查询原动作。无法核对的派发保持 UNKNOWN，停止后续队列并提示尚未发送的内容；不会重新输入。原生应用启用焦点报告后，焦点进入或离开产生的 `ESC[I` / `ESC[O` 也是真实输入动作，不能把它们归为零输入；验收按准确字节摘要与人工命令分别核对。

离页、网络提示变化或超过二十秒的前台重新核对保留原 shell 和已排空显示，撤去本窗口控制与未发送队列。已经发出的控制请求也随该窗口恢复失效；迟到的成功回执不能恢复控制，用户须根据新元数据重新点击接管。原在途输入仍只核对其原回执，恢复不会重发输入、尺寸调整、停止或启动请求。

## 输出与结束

Worker 将原始字节完整写入并强制保存到拥有的不可变段文件，再向核心发布 SQLite 游标引用。每段绑定原终端、epoch、绝对字节偏移、长度和 SHA-256；读取及导出重新核对实际文件与原归属。UTF-8 和 ANSI 可跨帧，游标单位始终是字节。

xterm 接收 `Uint8Array`，字节排空回调完成后才推进客户端游标。已有显示恢复到最后确认的游标；全新显示重读已保存范围。两种情况都只重放输出。epoch 变化、缺段、损坏、不可读和未发布尾部有独立状态，不能以空响应报告完整。

读取取消时，已经接受的原帧仍可完成同一 xterm 的排空回调；恢复读取等待该帧完成，再从确认游标继续。传输失败或 HTTP 5xx 仅允许在 1.5 秒间隔重新核对元数据和原输出 GET；身份、epoch 或字节完整性错误停止读取，生命周期事件不能解除该门禁。

已接受帧超过十五秒仍未确认排空时，保留原游标、错误和停止读取门禁，即使该帧原读取已被取消。迟到的排空回调或页面/网络恢复不能自动重新读取同一帧；用户可显式从保存起点建立新查看者，重新读取原已保存输出。该操作不新建 shell 或发送输入。

已保存原始文件、SQLite 已提交引用和调用方是否取得 ACK 是三种事实。提交前发布失败保持原游标；提交后 ACK 丢失保持实际已提交游标。核心重开不能补造引用、重放发布或把原 UNKNOWN 改为成功。原始输出可继续保存在独立文件或诊断前缀中，但未能发布或保存的完整范围不能推断恢复。

原 shell 退出码、原身份停止、已观察后代停止、输出读取与发布线程结束、EOF、拥有流关闭和原生资源清理分别核对。启动构造器未返回原生对象时，产品保存 PID 0、出生缺失、输出未完整及 UNKNOWN，要求独立核对 Worker 与原生进程；不推断进程未启动或已经清理。控制夹具覆盖这一丢失返回边界，不代表任意上游内部异常都已逐一观测。

已确认的手动退出或停止保存 EXITED / CANCELLED 活动回执，任务暂停、观察当前内容版本，当前验证和审查重置为 NOT_RUN；原模型预算、旧成功证据和历史尝试保持。停止按钮 ACK、终端 `endedAt`、任务 PAUSED 和根执行 `endedAt` 分别发布；完整导出必须等待准确的原终端 `taskExecutionId` 结束回执。

授权撤销、存储故障、核心/Worker 失联或结果缺失停止新增输入，并独立核对原进程。原任务、终端、根执行和不完整输出继续保留 UNKNOWN / UNCONFIRMED。撤权后没有完整终端返回时，不要求或补造终端 `endedAt`；原根 UNKNOWN 结束回执与实际原进程停止分别核对。人工核对沿用已有恢复门禁，旧活动与输出缺口不回写。

## HTTP 与限额

全部端点沿用核心 Bearer header 和项目授权，使用有界 HTTP 读取；无需把通用令牌放进 WebSocket URL。

| 端点 | 作用 |
| --- | --- |
| `POST /api/tasks/{id}/terminals` | 保存唯一原启动意图 |
| `GET /api/tasks/{id}/terminals?before=…&limit=…` | 稳定游标读取原终端历史 |
| `GET /api/terminals/{id}` | 读取原身份、状态、尺寸、输出范围和收尾事实 |
| `POST /api/terminals/{id}/control` | 核对代次并显式取得控制 |
| `POST /api/terminals/{id}/actions` | 提交 INPUT、RESIZE 或 STOP 的原意图 |
| `GET /api/terminals/{id}/actions?before=…&limit=…` | 读取原动作摘要与回执 |
| `GET /api/terminals/{id}/actions/{requestId}` | 核对原动作，不能触发重发 |
| `GET /api/terminals/{id}/output?epoch=…&after=…&limit=…` | 核对并读取原字节页 |

| 限额 | 当前值 |
| --- | ---: |
| 活跃终端 | 4 |
| 单次输入 | 16 KiB |
| 终端 JSON 请求 | 32 KiB |
| 单帧输出 | 64 KiB |
| 单终端持久输出 | 64 MiB |
| 单终端动作 | 32,768 |
| 客户端待发送队列 | 32 KiB / 64 动作 |
| 尺寸 | 2–500 列 / 1–300 行 |

核心在 JSON 解析前限制请求体，不能依靠输入字段解析后的校验阻止大请求。达到输出或存储边界时停止新增输入并保留已有事实；不删除必要输出来恢复“健康”状态。平台限制与长期负载覆盖分别记录。

## 交付、依赖与验收

任务 ZIP 包含终端记录、原输出来源与引用文件、原 Worker/根执行及进程观察。动作输入字节和控制凭据摘要不加入交付包；原始输出可能含输入回显。缺失文件、未提交前缀、不可读归属、旧任务版本和 UNKNOWN 效果分别列明，不能只因 ZIP 能下载就认证完整输出。

固定 pty4j 0.13.4 原 Jar 与 24 份原生资源在加载前核对 SHA-256，只提取到原 Worker 的私有拥有目录；固定私有 ConPTY 读句柄 ABI 也按原 class 字节核对。发行物携带 EPL、发布 Java sources.jar、SOURCE-OFFER、原生 MIT、xterm MIT 与 Kotlin/annotations Apache 许可。发布原生二进制的准确构建 commit 尚未证明，源码提供说明明确保留该范围。

`npm run test:ui:production` 用随机端口、自有服务器和冻结生产 dist 验证全部 UI。`test:terminals:http` 使用实际最终 Jar 验证原控制、完整输出及真实核心强杀恢复；`test:terminals:ui` 使用同源 Web 验证实际 CLONE/WORKTREE、尺寸、重开、停止和撤权。`test:terminals:packaged` 改用实际发行目录的 JRE、Jar 与 asar Web，逐文件核对资源，并在 PATH 中禁用外部 Java 和 Node，终端探针使用系统 shell 工具。发行 Electron 生命周期沿用独立原桌面验收。

本机成功、三端 CI、长期使用和完整历史进程树覆盖分别认证；原失败、UNKNOWN 与未上传的现场不由后续成功替代。固定来源及实现取舍见[终端研究](./research/terminals-2026-11-16.md)。
