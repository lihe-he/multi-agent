# 会话网页预览约定

协议版本 1，适用于 0.2.0-alpha.21。桌面预览使用 Electron 39 的 `WebContentsView` 和持久 `Session`；Java 核心保存配置，网页直接连接用户指定的服务。该协议不提供 HTTP 代理、远程端口转发或 Cookie 读取接口。

## 使用与范围

在项目的“协作会话 → 网页预览”填写允许访问的本机端口，再输入完整 HTTP 或 HTTPS 地址。“新建预览标签”建立同会话中的另一个页面，最多十二个标签、十六个端口。地址栏支持前进、后退、刷新、切换及关闭；活动标签随配置保存。

分区身份为核心持久 `serverId`、项目编号、会话编号和 `storageGeneration` 的 SHA-256。相同身份的标签共享该分区，其他项目、会话和代次使用不同分区。登录 Cookie、localStorage、IndexedDB、Service Worker 等保存在当前桌面用户目录中；完整退出后可恢复。同一核心的不同桌面用户目录拥有各自的浏览数据。

端口授权指向用户明确允许的本机服务端口，并不绑定或证明该端口背后的进程身份。服务停止后端口可能由其他进程接管。公开网页的 HTTP/HTTPS 地址也可打开；外部账号登录、站点策略与实际服务行为另行验证。

独立 Web 客户端维护相同元数据，并明确显示桌面能力提示。它不会创建与桌面等价的隔离浏览上下文，也不会返回 Cookie 或声称已清除桌面存储。

## 核心接口

下列接口沿用管理 Bearer 认证与现有项目、会话归属检查，路径前缀为 `/api/projects/{projectId}/sessions/{sessionId}/preview`。

| 方法与路径 | 含义 |
| --- | --- |
| GET 前缀 | 读取或首次建立预览配置 |
| GET `/authorization` | 核对会话仍打开、原本机执行节点启用且身份匹配 |
| POST 前缀 | 按 `expectedVersion` 更新端口、标签或活动标签 |
| POST `/reset` | 按当前版本推进存储代次并清空标签 |

配置包含 `version`、`authorizationVersion`、`storageGeneration`、`executionNodeId`、完整分区身份、`allowedLoopbackPorts`、`tabs` 和 `activeTabId`。每个标签只保存 `id/url/title`。版本冲突返回 409；关闭会话后拒绝修改和授权。未知字段、非整数端口、重复标签、凭据 URL 和不支持的 scheme 被拒绝。

普通标签更新只推进 `version`；端口变化另推进 `authorizationVersion`；重置同时推进配置、授权和存储代次。撤销端口会移除依赖该回环端口的标签。地址持久化只保留 origin 与 pathname，剥除查询参数与片段；登录回调完整地址只交给当前原生页面。路径及页面标题仍是持久元数据，不应包含需要保密的内容。

## 桌面导航与权限

预览页面无 preload、Node、webview、开发者工具或工作台管理桥接，开启 sandbox、contextIsolation 和 webSecurity。弹窗、下载、权限请求和设备权限均拒绝。顶层与 frame 导航只允许不含用户名密码的 HTTP/HTTPS；子资源和 HMR 另允许 WS/WSS。

核心管理端口在所有主机名、别名和 WebSocket 请求中均拒绝，即使用户把它填写为允许端口。回环地址及常见 IPv4/IPv6 表达必须匹配当前端口授权；该规则不宣称能抵御任意 DNS 重绑定或系统代理配置。

只有原工作台窗口的主 frame 能调用窄 IPC。每个公开动作携带原项目与会话编号；切换会话后，旧动作不能驱动新页面。打开操作在同一串行队列中先保存脱敏元数据，再直接加载完整地址，避免先请求脱敏登录地址。后续元数据同步保留当前页面的查询参数与片段。

宿主每秒核对当前授权，并在主动操作时重新核对。配置失效、会话关闭或核心无法核验时销毁旧页面；旧分区拒绝新请求，关闭现有网络连接。该轮询存在检测窗口，不承诺授权撤销瞬时阻断。关闭页面后已经发出的服务端效果也不能撤销。

界面隐藏、进入任务详情和打开工作台弹窗时暂停原生页面；恢复后按原分区重建。视图位置受实际可见区域、窗口边界和顶部导航约束。暂停会丢失页面内存状态，持久登录数据继续保留。

## 清理与失败

“清理站点”先销毁该 origin 的全部页面，再调用原生存储清理，覆盖 Cookie、localStorage、IndexedDB、Service Worker、Cache Storage 和文件系统缓存，并清理 HTTP 认证缓存。完成后重新建立页面；站点本身可能立即重新登录或写入新数据。Cookie 清理遵守 Chromium 的域规则，不保证按端口独立清理。

“重置会话存储”先在核心推进代次，使旧页面失去当前授权。桌面依据持久分区账本清理该会话的旧代次，包括前一桌面进程留下的分区；清理成功后才从账本删除记录。清理失败保留账本并显示错误，不能仅凭核心重置成功宣称 Cookie 已清空。独立 Web 的重置提示明确等待桌面再次打开。

本轮实际验证使用本地 HTTP 登录夹具和开发桌面，准确范围见[实施记录](./implementation-status.md)及[预览研究](./research/previews-2026-11-17.md)。发行包、外部 OAuth、远程节点转发和长期存储负载需分别验收。
