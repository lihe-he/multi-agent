# 0.1.0 开发预览版审查记录

本轮以计划书 1.1 为基线，由实现与独立审查分别开展。测试结果见实施记录及仓库 CI，未实测的供应商与操作系统不记为通过。

## 已修正的问题

| 问题 | 修正 | 回归依据 |
| --- | --- | --- |
| Git 文件清单混入标准错误与输出截断 | 标准输出、错误分离，元数据截断直接拒绝版本计算 | 真实 Git 克隆、中文路径、暂存及未暂存改动测试 |
| 二进制内容可混淆文件边界，执行位未完整绑定 | 版本标识采用长度前缀、文件计数、索引模式、实际执行位与逐文件 SHA-256 | 不同文件集合二进制分界测试、Git mode 变化测试 |
| 子命令结果未知被模型后续回答覆盖 | 子工具 UNKNOWN/CANCELLED 立即中止请求链，保留独立操作账本 | 请求次数与操作状态回归测试 |
| 原基线失败被同版本后续偶然成功覆盖 | 同版本同命令的基线失败参与验收门禁 | 基线失败、无代码修改、后续成功测试 |
| 审查目录或验收上下文变化仍可能被接受 | 审查副本与交付目录同时核对；验收再次核验记忆版本 | 审查副本变化、记忆编辑/停用及并发撤回测试 |
| 核心启动令牌被子进程继承 | 子执行环境移除平台专用环境变量；MCP 子服务独立处理凭据 | 带真实本地核心令牌的端到端验证及嵌套进程测试 |
| 残留核心与新核心可能共享同一数据目录 | 在打开数据库前取得跨进程文件锁，直到关闭才释放 | 同进程及第二 Java 进程争用、初始化失败后释放测试 |
| 新供应商配置可能继承旧密钥 | 只有引擎、供应商、地址身份一致时继承会话密钥 | 端点变化与路由版本凭据测试 |
| 导出遗漏新二进制/无末尾换行，或清单与实际内容不一致 | 使用 Git 原生二进制补丁；导出前后核对版本；拒绝敏感与截断导出 | 补丁应用后内容指纹一致、版本变化导出拒绝 |
| 目录准备完成但尚未写入任务状态时崩溃 | 独立准备意图与 READY 清单，可在核对后重新挂接一致现场 | 准备恢复检查；不完整准备现场保持待人工核对 |
| 精简 Java 运行时缺少 Tomcat 所需 GSS 模块，安装程序无法启动 | 打包模块集采用 Java SE 与必要 JDK 扩展 | 禁用外部 Java 路径后打包程序正常启动；内置运行时完整协议验收 22 / 22 |
| Windows 的 Git index 模式测试不能证明 Unix 实际权限变化 | index 场景显式关闭 filemode，另设真实 POSIX chmod 场景 | Windows index 回归通过；POSIX 专用用例明确条件跳过，交由跨平台 CI 实测 |

## 当前边界

代码提供可运行的开发预览：本地项目、固定三模式阶段、API 工具回路、CLI 适配、验证审查、人工验收、记忆、模板、独立 MCP 与桌面生命周期。固定阶段尚不能替代完整动态主副委派，独立 MCP 尚未自动注入 Agent 调用，目录隔离不等同于操作系统隔离。

外部供应商/原生 CLI 的真实任务、跨平台安装、完整备份恢复、选择性采纳、长期负载、动态协作与成本路由等，继续按原计划验收。M0–M3 全部门槛满足前保持开发预览标记。
