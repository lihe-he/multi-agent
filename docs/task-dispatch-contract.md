# 根任务派发与执行尝试

适用版本：`0.2.0-alpha.12`。SQLite schema 为 **6**，公开 API、实体版本与私有 Worker 帧协议仍为 **1**。只支持 schema 5 的旧核心拒绝打开新库。设计依据及验证范围见[队列研究](./research/dispatch-queue-2026-11-08.md)与[实施记录](./implementation-status.md)。

## 身份与确认事务

`TaskExecution` 表示一次根任务执行尝试，`DispatchAction` 表示该尝试唯一的待派发动作。它们独立于计划阶段、AgentRun、模型请求、Worker 逐操作租约及任务人工验收。

确认计划或显式继续时，核心在同一 SQLite 事务保存任务、递增尝试号、唯一动作与确认/排队事件。动作初始为 PENDING，`dispatchCount=0`。确认或任一记录写入失败时全部回滚，核心封闭新增执行；没有实际 Worker 操作、模型请求或预算消耗。

每次尝试固定完成约定版本、执行授权版本、策略版本与预算起点；动作保留完成约定、节点/仓库绑定、路由、硬锁、MCP 授权与协作限制快照。新动作不能绕过旧根执行或外部效果的核对要求。暂停、取消和重开均不重用尝试号。

## 排队与领取

平台线程每 500 毫秒按持久行号有界扫描最多 64 个 PENDING 动作，并轮转扫描位置。内存集合只防止重复安排候选，不表示动作已领取。执行器拒绝、核心关闭或候选尚未进入实际线程时，数据库中的原动作仍为 PENDING。

实际执行线程进入后，领取与用户暂停/取消共用核心锁。领取重新检查原状态、版本、任务/尝试指针、冻结授权、路由/凭据、磁盘、当前 Worker/节点归属和原进程恢复门禁。SQL 再次限制 PENDING、原版本、零领取数及 QUEUED 的任务/尝试；零行更新不写任务、尝试或事件。领取成功在同一事务保存 CLAIMED、`dispatchCount=1`、RUNNING 尝试与领取核心的 session/PID/出生时间，然后才开始现场和模型执行。

条件未满足时保留原动作和等待原因。界面查询、翻页和轮询不领取动作。修正路由、补充会话凭据或完成旧进程核验后，派发器重新检查原动作；冻结授权变化则需先暂停，重新确认授权，再显式继续建立新尝试。

当前只有一个 SQLite owner。动作唯一索引限制每个尝试一条动作、每个任务最多一条 PENDING/CLAIMED 动作；尝试号在任务内唯一。公开 API 没有客户端领取、回执或更改动作身份的入口。

## 状态

| TaskExecution 状态 | 含义 |
| --- | --- |
| QUEUED | 已保存尝试，原动作尚未领取 |
| RUNNING | 原动作已由当前核心领取 |
| SUCCEEDED | 本次执行已返回并完成收尾；任务可仍等待人工验收 |
| FAILED / WAITING_INPUT | 执行失败或需要用户处理，原原因与预算保留 |
| PAUSED / CANCELLED | 未开始尝试已撤回，或实际执行按原停止路径结束 |
| UNKNOWN | 已领取后缺少完整结束回执，或存在未确认效果；禁止自动重放 |

| DispatchAction 状态 | 含义 |
| --- | --- |
| PENDING | 尚未领取，领取数为 0 |
| CLAIMED | 已领取一次，实际执行及收尾尚未完成 |
| SETTLED | 已取得根结束回执 |
| WITHDRAWN | 未领取时暂停/取消，领取数仍为 0 |
| UNKNOWN | 已领取后根结果未知；原领取数仍为 1 |

执行结束保存 `endedAt`、`elapsedMs`、`taskStateAtEnd`、`taskOutcomeAtEnd`、预算起止快照、现场与结果版本。`elapsedMs` 从入队时间计算，包含等待。运行成功、独立审查意见和人工验收分别保存；验收不会把原 `taskStateAtEnd=AWAITING_ACCEPTANCE` 改为 COMPLETED。

## 暂停、关闭与重启

暂停/取消未领取动作时，任务状态、WITHDRAWN 动作及未开始尝试的结束记录同事务保存，不生成 Control，也不发送 Worker/进程停止信号。领取获胜时沿实际 Control、Worker、后代与 MCP 路径停止，停止请求不能证明外部效果已经撤销。

正常关闭停止扫描并保留未领取动作。重开同一目录时，PENDING 保留原尝试和动作编号，继续受原进程覆盖与授权门禁约束，条件满足后由新核心领取一次。CLAIMED 没有根结束回执时，原动作和尝试保存 UNKNOWN，原请求、已承诺调用与预算保持原样，不自动重放。

原进程/覆盖核验与任务文件/外部效果核对分别进行。任务核对保存 USER 来源、时间与说明，给原 UNKNOWN 记录补充 `reconciliation`，保留 UNKNOWN 状态。下一次显式继续创建新的尝试和动作，累计预算不清零。旧版本只有 QUEUED 文字、没有独立根动作的任务保留旧 UNKNOWN 恢复语义，不推测补造“从未领取”的证据。

## 来源与查询

实际操作、根/副 AgentRun、子任务、模型请求、Worker 租约、证据、团队操作及 MCP 原模型来源保存 `taskExecutionId` 和 `dispatchActionId`。它们从原任务或父运行派生，旧记录缺失来源时不补造。Worker 与 MCP 新操作检查当前核心已经领取的根来源，旧尝试、未领取或已结束根不能取得新租约或承诺 MCP 预算。

| 接口 | 返回 |
| --- | --- |
| `GET /api/tasks/{id}/task-executions?before=0&limit=30&state=` | `{executions, cursor, hasMore}`，每项包含原 `dispatchAction` |
| `GET /api/tasks/{id}/dispatch-actions?before=0&limit=30&state=` | `{actions, cursor, hasMore}` |

接口沿用本机管理令牌鉴权，项目 MCP 只读令牌不能访问。默认每页 30 项、最多 100 项，按持久行号倒序；上一页 cursor 用于 before。状态须为对应协议中的精确状态，无效状态或负游标返回 400，任务不存在返回 404。读取历史后新增尝试不会改变原分页位置。

任务详情的“任务派发”页展示尝试、动作、领取次数、固定版本、核心来源、预算与核对历史，轮询保留当前筛选和历史位置。任务摘要同时保存当前 `taskExecution` 与 `dispatch`；这些摘要不能代替完整历史。

## 导出与验收

验收、重新验证、预算/MCP 配置修改及导出等待根结束回执。任务文字已经到达等待验收而根仍在收尾时返回 409；导出生成前后复查根状态、文件版本和任务记录，拒绝把变化中的任务与旧补丁混合交付。

任务 ZIP 包含完整 `task-executions.json` 和 `dispatch-actions.json`，以及原 Agent、请求、租约、进程、MCP、团队和事件记录。人工核对后的 UNKNOWN 与随后新尝试都保留。公开租约仍移除领取摘要，包内不包含凭据。

## 可重复验证与范围

`npm run test:dispatch` 使用当前最终 Jar、实际 SQLite、独立 Worker、HTTP 模型夹具与生产 Web。外部 `PropertiesLauncher` 夹具只替换根执行器，以受控屏障保留未领取动作；它不声称复现操作系统调度故障。重开执行使用普通生产 JarLauncher。批准事务故障、未领取撤回、原编号重开领取一次、领取后崩溃 UNKNOWN、人工核对/新尝试、累计预算、完整 ZIP 与桌面/430px 页面分别验证，失败与清理事实保存在每次独立运行目录。

本轮覆盖本机根队列。动态副任务仍沿团队与逐操作租约执行；远程拉取/配对、完整历史进程树、角色/写入租约、任意 workflow、定时与漏跑策略、完整备份及长期负载继续实施。本地一次领取不能证明任意外部系统的效果恰好发生一次。
