## 已确认问题

### P1：原生 CLI 的工具参数不足以隔离继承的外部配置

位置：`WorkspaceRuntime.run` 的 Codex 与 Claude 参数构造。

当前 Claude 适配使用 `--tools Read,Glob,Grep`（只读阶段）和 `--disallowedTools Bash`。本机 Claude Code 2.1.202 的 `--help` 明确说明 `--tools` 限定的是 built-in set，而另行配置的 MCP、hooks、插件等不由这个参数统一禁用。因此，平台未选择外部 MCP 动作，或运行只读调查/审查阶段，仍可能通过继承的原生配置产生平台未授予的外部副作用。

本机 Codex 0.166.0-alpha.6 的 `exec --help` 将 `--sandbox` 描述为执行模型生成 shell 命令的策略。该参数不能单独证明已配置的外部服务受任务固定动作授权约束。适配器也未禁用继承的用户配置。

可用证据与处置方向：

- Claude 帮助提供 `--strict-mcp-config`，只加载显式 `--mcp-config` 中的服务；`--safe-mode` 可禁用 CLAUDE.md、skills、plugins、hooks、MCP、commands、agents 等自定义项，同时保留认证、模型、内置工具与权限。
- Codex 帮助提供 `--ignore-user-config`，不加载 `$CODEX_HOME/config.toml`，认证仍使用 `CODEX_HOME`；具体版本是否还会加载其他配置来源需验证，不能仅凭参数名视为全部隔离。
- [OpenAI 官方 CLI 参考](https://developers.openai.com/codex/cli/reference) 已实际获取，并与本机帮助比对。现有适配器传入的参数在本机帮助中存在。
- 修复应隔离所有可扩权配置，或对无法强制约束的原生阶段明确拒绝执行。当前状态：已通知实现负责人，待代码与回归证据。

本次只执行 `--version`、`--help` 与文档读取，没有启动外部模型任务；因此不据此确认账号、模型访问、运行结果协议或实际供应商调用能力。

## MCP 契约审查

依据：[MCP 任务自动调用契约](./mcp-task-contract.md)。本轮采用 API 实现/修复阶段的固定参数动作，模型只能选择无参数别名；全部外部 MCP 在只读阶段禁用。该边界比通用动态参数更容易核查，但仍需以下实现证据。

| 边界 | 必须满足的行为 | 当前状态 |
| --- | --- | --- |
| 固定授权 | 派发前复验项目、服务身份、配置版本、定义版本、工具白名单与授权版本；不能只依赖创建任务时检查 | 待实现审查 |
| 固定参数 | 拒绝模型附加参数；schema 不支持的结构拒绝自动动作；参数不作为凭据通道 | 待实现审查 |
| 幂等动作键 | 对象键递归规范化；改变授权版本、超时或配置版本不能绕过同动作只派发一次；旧服务回执不能冒充新服务结果 | 已告知负责人，待回归 |
| 未知覆盖根任务 | 任一子操作 UNKNOWN 后停止模型请求和新工具；主任务、恢复、重启、验收与导出均不能忽略 | 待实现审查 |

## 建议的回归场景

1. 重排固定参数对象键、修改超时、重新授权后再次选择同动作，外部调用计数仍为一次。
2. 工具响应丢失或取消时仍有进程存活，子操作与根任务均为 UNKNOWN，后续模型请求数不增加。
3. 核心在预算登记、PREPARED、DISPATCHED、收到回执但未落库等边界退出，恢复不重复派发。
4. 两个任务争用同服务时取消等待者，及时返回且不持有模型资源。
5. 只读阶段收到模型伪造工具名/参数；授权、定义、服务身份或项目权限在派发前改变，均不发出业务调用。
6. ACK 回执携带 `isError=true` 时保留业务失败；用户核对 UNKNOWN 后仍不把它变成历史成功。

本轮回归结果将在实现稳定后补充；0.1.0 的历史通过记录不能代替上述新增能力的验收。
