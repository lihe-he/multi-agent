# 文件版本与操作回执

本约定适用于 `0.2.0-alpha.15` 的本机 API Agent 文件工具。公开 API、实体与 Worker 帧协议仍为 1，SQLite schema 仍为 8；文件工具日志协议为 2，`/api/health` 的 `fileToolProtocolVersion` 为 2。根工作区保护继续遵循[根写入保护约定](./workspace-write-contract.md)。

## 读取与版本

每次 API 执行建立独立文件会话。`read_file` 完整读取不超过 256,000 字节的 UTF-8 普通文件，成功后返回不可预测的 `readVersion`、`fileVersion` 与原读取操作编号。无效 UTF-8、超限、非普通文件或读取过程中现场变化均不发出可授权覆盖的回执。

`inspect_file` 取得普通文件的元数据与有界 SHA-256，不返回文件内容；单文件上限为 32 MiB。它可授权删除，不能代替完整文本读取授权覆盖。不存在的目标可取得不存在回执。路径解析与权限范围沿用原工具门禁。

版本包括存在状态、SHA-256、原生文件身份、大小、修改时间、可执行状态和适用的 POSIX 权限。回执绑定本次执行与实际文件路径，不能用于其他路径、其他执行或重启后的执行。模型读过的正文与读取授权回执分别处理，日志只保存必要版本事实，不保存完整正文。

## 覆盖、新建与删除

覆盖已有文件时，`write_file` 必须提供本次执行完整 `read_file` 返回的当前 `expectedVersion`。成功写入会发出新的可用文本版本回执。工具先比较原版本，再完成同目录临时文件并同步内容，保留原 POSIX 权限，最后再次核对现场并进行原子替换。

新文件使用 `ABSENT` 或本次不存在回执；空值仅兼容真正未读取过且当前不存在的目标。新建通过已完成临时文件的硬链接原子占位；目标先出现时拒绝创建。文件系统不支持所需原子操作时保持实际失败，不降级为覆盖。

`delete_file` 必须提供当前 `read_file` 或 `inspect_file` 回执。读取后目标消失、内容变化、身份变化或权限变化均拒绝原删除。成功删除返回不存在版本。删除后目标再次出现时保留新文件，原操作效果保持 `UNKNOWN`。

版本冲突保存为 `REJECTED` / `FILE_VERSION_CONFLICT`，保留当前文件。模型需重新读取或检查并决定后续操作；仍有未解决冲突时，即使模型声称完成，执行也进入 `WAITING_INPUT`。工具效果已发生但最终确认、临时文件清理或工具租约收尾失败时保存 `UNKNOWN`，不继续模型请求，不重放原写入。

同一 JVM 的文件工具使用共享条带锁串行处理相同目标。任意外部进程仍可能在最后比较与替换之间写入，因此本协议不提供跨进程通用 compare-and-swap。原生 CLI、命令、MCP 和跨核心动作也没有取得一般文件版本事务能力；当前目录执行及跨核心现场协调仍在实施。

## 查询、来源与完整导出

认证接口 `GET /api/tasks/{taskId}/file-tool-operations?limit=30&before=&state=` 返回本任务根现场及同任务所有 AgentRun 现场的四种文件工具记录。单页最多 100 条。历史按原 SQLite entities rowid、受限工具序号与 UUID 排序；游标使用完整长整数，稳定分页不依赖可变更新时间。

协议 2 记录原模型请求、工具调用编号、实际工具顺序、原始参数 UTF-8 的 SHA-256 及经过格式过滤的请求版本。版本回执保存原读操作、操作前后摘要及新回执。只有同任务、成功原请求和原 AgentRun 工作区对应时，记录才标记 `REQUEST_BOUND`；原 Worker、核心、根尝试与动作来源取自原请求。该标签证明请求关联，不是对日志全部内容的独立签名。旧日志和无法验证的日志明确标注，不从传入 `source` 伪造 Worker。

读取日志仅限配置数据根；拒绝外来符号链接、junction、坏 UUID 名、记录编号不符、超限文件及读取期间目录或文件身份变化。合法 Windows 8.3 路径别名按原物理目录核对。缺失日志保留 `journalPresent:false`，界面明确显示此事实。

每个新独立审查副本使用各自父目录下的 `work`，操作清单与其他任务及重复审查分别存放。旧版 `reviews/operations` 共用目录且缺少逐条现场归属；存在这种清单时，查询及完整ZIP返回409并保留原文件，不能猜测归属或混入其他任务。

单次快照上限为 50,000 条、累计日志 32 MiB；超限返回错误，不截断为成功。ZIP 一次收集完整快照，分别包含 `file-tool-operations.json` 和 `file-tool-journal-sources.json`，分页与状态筛选不缩减导出。原任务版本、现场版本与执行收尾门禁继续生效。自由文本及任意扩展键递归脱敏在 JSON 编码前完成，含引号、反斜杠的凭据同样覆盖。固定协议键和格式有效的枚举、UUID、摘要、读回执、时间及原生文件身份保留，避免短凭据替换损坏状态和游标；无效版本文本仍脱敏。格式核对不为日志内容提供独立签名。

任务详情“文件操作”页显示已消耗和新签发的版本、冲突、原请求与读取/修改来源；可筛选、分页并定位原模型请求。未验证记录不展示伪造的 Worker。缺失日志、等待重新读取及未知效果保持各自原状态。
