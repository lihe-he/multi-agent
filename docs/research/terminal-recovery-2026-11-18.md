# 回环连接核验与终端读取恢复

日期：2026-11-18。基线 `cfc259a5d24f8fab38a2059552444a67f0b7c046`，继续计划书 9.6、13.4、18.2 与 F01 的客户端恢复要求。

## 固定开源来源

沿用[页面恢复研究](./page-recovery-2026-11-18.md)中的 OpenCode 固定提交 `59ed43f0b8da891f03a7333d540a7b0c428049ea`。`packages/client/src/solid/connection.ts` 的原字节 SHA-256 为 `3b93c8ba83bd7b77bfb6901fa27d062f90e65007a8db0694731c0eab21c19d32`，Git blob 为 `01e6b75b28c1c84d705c74b5f5f31063cc03d6c0`；源文件、测试及生命周期场景的字节与固定树已核验。

该连接实现提供网络变化后的重新核对、读取取消与返回前台超过 20,000ms 后同步的参考。本项目保留自己的核心授权、终端代次、字节完整性、控制和动作账本边界，没有复制或执行上游代码，没有增加运行依赖。

## 回环核心可达性

上一轮将浏览器离线提示作为停止读取的条件，会阻止仍可达的本机 Java 核心初始化。浏览器 `navigator.onLine` 现在只触发实际端点核验：初始提示离线仍读取配置；网络提示变化取消旧读取并立即核对原端点，重复事件不增加读取。连接状态由实际读取结果决定。

离页取消定时器与当前读取，实际原缓存文档返回后继续读取。返回前台时，如距上次读取已超过二十秒，重新核对原端点。明确失败并返回停止标记的配置初始化仍须用户点击“重试连接”；生命周期事件不重读该配置，不清除原错误，不创建任务或重放写操作。

## 原终端输出与控制

终端列表、元数据、原字节和动作历史沿用页面生命周期管理。保留同一 xterm 和最后排空的字节游标；已接受的原帧可以在读取取消后完成真实排空回调，只有该回调完成才推进游标。恢复读取等待旧帧排空，然后从原确认游标继续；取消前尚未接受的旧响应不进入显示。

仅传输失败与 HTTP 5xx 的 GET 读取可在 1.5 秒间隔重读，并先核对新元数据。原身份、epoch、摘要或协议不一致仍停止读取；页面、网络和可见性事件不能解除该门禁。八秒终端请求期限及原输入/输出限额保持。

离页、网络或前台重新核对时，清除本窗口控制和未发送队列。已发送的 INPUT、RESIZE 或 STOP 保留原请求及回执核对规则，恢复不重发它们、不重建 shell、不自动接管或调整原终端尺寸。

审查还发现：取得控制的原请求可能在恢复完成后才返回，届时元数据又已可读，单靠可读状态会接受旧控制凭据。现在清除控制同时废弃本窗口的旧控制请求；迟到的成功或失败回执不恢复控制，也不覆盖新的恢复提示。核心已经接受的控制代次仍是事实，用户重新点击时基于新元数据显式申请下一代次。

## 原失败与回归范围

回环连接的旧生产资产负对照未读取 `/service` 配置，原失败保持。修复前的终端读取负对照在原 5000ms 内没有显示 `READ_TRANSPORT_RECOVERED`，读取仍停在中断状态，原生产资产及失败现场另存。

新增终端恢复用例的首次运行 46/48：两项唯一性断言把 xterm 的屏幕阅读器树和独立实时公告区一起计数，因公告回显而失败。安装的 xterm 6.0.0 原 `AccessibilityManager.ts` 分别创建 `.xterm-accessibility-tree` 与 `.live-region`；新增断言改为等待和计数实际树行，原游标、请求、控制与排空断言保持。原失败不改写，修正后的 48/48 单独保存。

随后中间生产资产完整 UI 248/248，零失败、跳过或重试。新增迟到控制响应的 page、network、foreground 三项负对照均失败：新读取和显示已经恢复，旧成功回执仍把窗口改为控制模式。三个原 trace、截图、源码与资产保持。修复后的完整 UI 增为 251 项。

251 项及当时的实际核心、开发/发行终端与开发/发行预览均通过后，继续审查已接受帧的排空期限。新增回归使用原 15,000ms 实际期限，原取消读取在期限后丢弃排空错误，恢复读取再次从 `after=0` 接受同一帧；原附件确认两个零游标 GET、两次帧交付，界面仍显示恢复等待而没有错误。原失败保持。现在已接受帧的排空超时与被取消的传输错误分别处理，超时保留错误和停止读取门禁；页面、网络及迟到排空回调不能释放它。用户显式建立新查看者后才从保存起点重读，原限额和十五秒期限不变。完整 UI 因此增加到 252 项。

最终产物的第一次完整运行为 251 通过、1 失败：新增用例的停止读取门禁和显式新查看者均已通过，但最后计数在 xterm 的异步屏幕阅读器树写入前取得空文字。只在该新增用例中等待原树文字后再执行原唯一性断言；产品源码和生产资产保持，游标、请求次数、十五秒期限及唯一性断言没有改变。修正后的定向 1/1 与完整 252/252 分别通过，原失败保留在 `.runtime/ui-production-4nGfgb`。

page/network/foreground 迟到响应用例使用浏览器协议夹具；其中前台旧读取通过受控时钟差触发，不能作为一次操作系统休眠验收。实际浏览器断网的原生终端工具分别检查 CLONE/WORKTREE 的原 PID、出生时间、epoch、单次手工效果、原排空游标及恢复后的授权 GET，并要求保持查看、没有额外终端 POST。

首次实际终端跟进在新增尺寸输入响应等待中失败：工具错误地匹配请求中不存在的 `sha256`。原代理记录证明两次手工 INPUT 均 HTTP 200、ACKNOWLEDGED、一次派发和一次原生授权，字节摘要与回执相同，实际尺寸 `22 144` 和手工效果计数 `1` 已写入。请求实际通过 `dataBase64` 发送字节；等待改为匹配准确原字节与 `/service/api` 路径，保留原三十秒时限及原一次命令、尺寸、原进程、预算和撤权断言。该失败属于新验收观察的字段错误，不归因于产品传输或恢复。
