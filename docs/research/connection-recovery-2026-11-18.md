## 证据与问题边界

多轮 macOS 原始 CI 在不同业务用例的共同任务入口失败：配置请求 HTTP 200，trace 中没有 `/api/state`，页面显示 `signal timed out`。最新基线 [run44263865457](https://github.com/lihe-he/multi-agent/actions/runs/44263865457) 的 macOS 核心 563 项、零失败/错误、11 条跳过，生产 UI 229/230；失败仍为 diff-view 的共同任务入口。最新选取 trace 显示配置响应约 953ms，不能仅凭这个数证明整个初始化在五秒内完成，亦不能据此确定浏览器调度、响应体处理或运行环境中的唯一原因。整条 CI 结果另记，不能将连接恢复功能记作已证明的根因修复。

本机可确定的问题是：初始配置失败后没有页面内重读入口；手动验证连接只发起单次刷新，原初始化失败后的持续轮询没有重建；旧配置或旧状态迟到时可能覆盖后来手动设置的地址、令牌或项目。新增 HTTP503 用例在修改前冻结生产资产上因缺少“重试连接”按钮失败，原失败保留。

## 实现

连接横幅增加“重试连接”，正在连接时禁用。初始化未成功时，明确重试重新读取公共配置；初始化成功后，继续核对当前连接。配置读取沿用五秒，状态读取沿用三十秒，完成后沿用三秒轮询间隔。未增加初始化自动重试，未重放任务或写操作。

每次连接尝试拥有 AbortController；重试、已验证的手工连接及卸载终止旧尝试和计时器。初始化仅在原连接对象仍为当前对象时发布结果，防止旧响应覆盖新选择。状态刷新同时核对原连接对象和取消信号，旧成功、失败及结束状态不回写新连接。令牌仍使用原当前浏览器会话范围，公共配置仍只允许 apiBaseUrl。
