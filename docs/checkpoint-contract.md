# 文件检查点与撤销约定

对应 F04 与计划书 9.4、13.2、13.3。当前开发协议 `checkpointProtocolVersion=1`，API/Worker 帧仍为 1，SQLite schema 为 9。实施与真实验证状态以[实施记录](./implementation-status.md)为准。

## 保存边界

任务实际隔离根目录支持文件检查点。所选 clone/worktree 先核对原 READY 准备回执、任务归属和 Git 关联；旧独立 clone 核对原准备清单。根就绪、阶段开始/结束、执行结束和原 API 工具成功完成分别保存，用户可在已停止的任务上手动保存。

文件内容按 SHA-256 去重，清单及内容对象完整落盘并按摘要读回后，才提交 SQLite 可见引用。清单保存新增、修改、缺失/删除、二进制和空文件字节、实际 POSIX 权限、固定 HEAD、内容版本、原 index 字节及暂存 blob。HEAD 与 index 在捕获前后重查，文件读取同时检查原摘要与身份。文件归档和 SQLite 记录不能用阶段文字标识相互替代。

暂存对象通过有界 `cat-file` 批协议读取，每批最多256项、内容输出最多2 MiB。信息与内容分别核对原对象编号、blob类型、长度、分隔符和完整 Git 哈希，截断或额外输出均拒绝。原生管道输入使用独立平台线程，输出保留原两个载体限制；输入、输出和错误输出都完成后才接受进程回执。归档文件执行 `force(true)`，POSIX 发布目录项前另外同步父目录，恢复 Git 对象显式使用 `core.fsync=objects` 与 `core.fsyncMethod=fsync`。这些回执不是断电恢复实测。

一次捕获中相同字节只发布一个内容对象，清单落盘后仍独立读回全部引用。单次清单读取按原 SHA-256 核对每个不同对象一次，各文件、index 和暂存引用分别检查长度、各自限额及 Git 哈希；核验事实只在本次读取内使用，下一次捕获或导出重新读取。实际文件身份、目录解析与捕获前后的一致性核验继续保留。

HEAD、对象格式、Git/index目录和 shared index 由同一有界 Git 回执读取，捕获前后重新核对整组，完整 index 字节、暂存清单与文件内容仍分别核验。未启用 split index 时 Git 省略 shared index 输出；只有末项允许缺省，其他字段缺失或额外输出均拒绝。POSIX 文件恢复保持原写通道打开，设置只读权限后完成同一文件同步，再发布目录项。

捕获使用带状态前缀的同次 Git 文件清单区分暂存记录与未跟踪路径，含 tab 的字面文件名不会被当作 index 头解析。收尾独立重读清单与全部文件字节。当前实际 Git 目录、公共目录、worktree 反向关联、原锁定原因与 detached HEAD 同时核对，原选择记录在捕获前后完整比较；Windows 普通短路径可匹配实际根，重解析目录仍拒绝。旧 clone 准备与恢复返回规范目录，已保存任务中的旧路径文字保持。

普通内容指纹也从一次带状态的Git清单取得成员与模式，继续使用原v2摘要算法、最后暂存阶段的模式及每次完整文件读取。真实SHA-1/SHA-256仓库的固定旧版本、未合并阶段、skip-worktree、删除和字面文件名已有兼容回归；检查点保存仍要求完整合并的可恢复index。

Git 差异和交付路径读取使用每次独立的私有 index 副本，Git 的内容核对与时间缓存刷新只写该副本；原 index 在读取后逐字节重查。私有读取禁用 split index 写入，原共享对象保持。直接 Git 读取仍禁用可选锁和差异缓存刷新。纯时间变化不加入交付路径，原敏感文件拒绝规则、完整补丁和输出上限保持。私有目录使用规范的数据路径，普通 Windows 短路径可解析，新建目录的重解析入口仍拒绝。

元数据保存阶段和计划状态、会话、上下文编号/版本、已有成果编号、累计预算观察、原根尝试/派发来源以及已有未知操作编号。工具检查点另外绑定实际成功的模型请求、文件操作、原 Agent 运行和根写入归属，原 Worker PID/出生必须与捕获进程匹配。副 Agent 的独立目录当前不冒充根目录检查点。

当前上限为单文件或暂存 blob 256000 字节、单次文件与暂存内容合计64 MiB、清单或 index 16 MiB、最多20000条文件清单。Git 原元数据输出上限继续生效，超限清单不会截断发布。敏感路径、超限文件和不可完整保存的暂存区分别标记 `EXCLUDED`、`LIMIT`、`restorable=false`。含未合并 index、链接或子模块的现场被拒绝。共享 index、排除或超限暂存对象不能当作可完整恢复的 index。当前没有自动清理检查点或 UNKNOWN 日志的策略。

## API

所有接口继续使用本机连接鉴权，任务编号与归档原引用须一致。

| 请求 | 输入与结果 |
| --- | --- |
| `GET /api/tasks/{id}/checkpoints` | `before` 为稳定 SQLite 行游标，`limit` 默认30、范围1–100；返回可见检查点、`cursor`、`hasMore`、`sourceCheckpointId`、`undoAllowed` 和阻塞说明 |
| `POST /api/tasks/{id}/checkpoints` | 只接受可选 `label`，文本不超过100字符；返回已核验的原归档描述。名称经核心脱敏 |
| `POST /api/tasks/{id}/checkpoint-restores/preview` | 只接受 `checkpointId`；目标必须是同任务最新保存边界之前的可见检查点 |
| `POST /api/tasks/{id}/checkpoint-restores` | 只接受原 `previewId`；重新核对后将该预览与新的根尝试、待派发动作同事务排队 |

保存、预览和确认只允许 `PAUSED`、`WAITING_INPUT`、`FAILED`、`AWAITING_ACCEPTANCE`。原根收尾、Worker/MCP/子执行停止、未知操作、实际写入归属和健康存储的检查继续生效。已取消或已验收任务不能借撤销重开。历史检查点查询仍可读取；页面读取时的许可不能替代确认时的重新核验。

## 预览与文件撤销

预览比较“目标检查点 → 最新保存边界”的反向文件改动，并独立保存预览时的当前现场。该内部现场不进入用户检查点列表，也不推进最新任务保存边界。预览记录原目标、来源、当前三侧引用、最多100个受影响路径、index 是否改变、冲突及15分钟有效期。

受影响文件有后续内容、身份、权限或暂存修改时，整个预览不可执行。涉及排除或未保存内容时也不可执行。没有参与反向改动的后续文件保留。确认时当前内容版本、固定 HEAD、原 index 与受影响文件身份必须仍匹配预览；保存边界变更、到期、冲突或重复确认均要求新预览。HEAD 始终保持。

index 不需要恢复时保留当前完整 index；需要恢复时要求它仍匹配原保存边界，取得独占 `index.lock`，核对原 index/锁身份、归档暂存对象后恢复目标原字节。仅 index flags 变化可以没有文件写入，仍有明确预览和确认。撤销逐文件核对原身份及内容，创建使用排他路径，替换使用同目录原子操作。未参与路径在结束时再核对。

确认后的撤销由新的原根尝试消费，沿现有 `TaskDispatchQueue`、Worker 租约、原操作类型 `CHECKPOINT_RESTORE` 和整次根写入保护执行。撤销不申请模型调用；调用预算、旧任务执行、模型/文件回执、会话和验收历史继续保留。运行器凭据与模型额度不构成文件撤销的额外前提，节点/仓库授权和原 Worker 归属仍须有效。

## 回执、停止与恢复

预览状态依次为 `PREVIEW → QUEUED → DISPATCHED → APPLIED`。尚未派发时随根暂停/取消转为 `CANCELLED`；原 Worker 在文件效果开始前明确拒绝时为 `REJECTED`。文件部分效果、原回执丢失、收到结果后失去归属或元数据未完整发布保持 `UNKNOWN`。

本地撤销日志保存原三侧引用、原操作编号、受影响路径、当前处理路径、已写路径、状态及完成结果。原 Worker 成功返回值先保存为核心观测，再核对租约并发布任务成功状态；观测不能当作已确认成功。SQLite 操作 ACK、本地 `APPLIED` 与核心 `UNKNOWN` 可同时存在，分别保留。

SQLite 写入失效会封闭并停止原 Worker。原进程停止后操作系统可以释放其文件锁，持久写入租约仍可能为 `HELD` 且 `protectionReleased=false`。故障验收分别保存锁探针和原 PID/出生身份的前后观测；探针取得锁时必须独立确认原 Worker 已停止。进程停止和锁可取得不补造释放回执，也不解除原 UNKNOWN 效果的核对门禁。

成功后任务为 `PAUSED`，内容版本更新，验证/审查为 `NOT_RUN`，必要验证、审查和交付阶段重新等待。目标之后的成果编号标记失效，原证据和输出继续可查。阶段状态根据目标清单重组，预算及旧历史不倒退。界面要求新现场重新验证，不能用原绿色回执宣称当前现场已通过。

当前问题列表随新现场清空，旧审查问题仍在原证据输出中保留。历史列表可在自身范围滚动，窄屏预览不会被全部历史记录推到页面末端。

核心重启不重放已领取撤销。原未领取请求保留编号及零派发事实，经原进程覆盖核验后继续排队检查；用户可以暂停/取消。人工核对原效果只解除继续工作的门禁，旧 UNKNOWN 和原日志保留，旧预览不能再次执行。新的文件操作需要新预览。

## 交付包

任务 ZIP 包含 `checkpoints.json`、`checkpoint-restores.json`、原日志来源及以下内容：

- `checkpoints/tasks/{checkpointId}/manifest.json`：按原已保存 SHA-256 读取的清单。
- `checkpoints/objects/{sha256}`：全部被引用的文件、index 和暂存内容对象，按摘要去重。
- `checkpoints/restores/{operationId}/manifest.json`：原操作的本地进度日志，原 ACK 摘要存在时同时核对。

每个清单及对象重新核验摘要，日志缺失与实际文件效果分开记录。UNKNOWN 本地结果中尚未发布 SQLite 成功引用的结果检查点也随原日志导出。历史查询不使用页面上限截断；完整检查点内容累计超过128 MiB或100000项时拒绝导出。

UNKNOWN 撤销允许保留不匹配的两侧事实：根任务原 `version`、读取时 `workspaceVersion`、`workspaceMatchesRecordedVersion=false`、`unknownRestoreEffects=true`。当前补丁不能代替旧成果的验证版本。导出结束再核对原任务、检查点/撤销记录、日志和当前文件，变化时拒绝混合包。其他任务仍沿用版本匹配门禁。

结构化 `backup` 继续明确为 `STRUCTURED_STATE_ONLY`，尚不包含全工作区、归档对象与配置的完整灾难恢复快照。根目录外的副执行归档恢复、完整 workflow/原生会话接续、原项目局部采纳和长期保留治理属于后续范围。
